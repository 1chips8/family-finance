# 家账“家庭月报”扩展与视觉重塑设计

## 1. 目标

在保留现有注册、家庭、权限、分类、流水和统计闭环的基础上，将产品从“通用记账后台”升级为具有明确记忆点的“家庭月报”。本次设计同时完成预算、CSV 导入导出、周期流水、统计增强、操作日志五项扩展，并修复已识别的前端日期、路由、可访问性和包体问题。

完成后的系统仍定位为本机运行的软件课程设计项目，不接入银行、支付平台、短信、云存储或后台任务基础设施。

## 2. 产品与视觉方向

### 2.1 核心概念

产品的核心叙事是“每个月，家庭共同读懂一份生活报告”。仪表盘不再表现为一组同质化 SaaS 卡片，而是一张具有编辑排版感的家庭月报：月份是视觉锚点，结余是主数字，收入、支出、预算和成员贡献围绕月度故事组织。

### 2.2 视觉语言

- 背景使用米白纸张色，正文使用近黑墨色。
- 朱红用于月份标记、关键操作和支出强调；竹青用于收入和健康状态；群青用于结余和中性数据。
- 顶部采用黑色横向导航；桌面端增加朱红色月份侧标，移动端将月份侧标折叠为横向月报标题。
- 通过细分隔线、留白、强数字排版和少量大色块建立层级，减少大量相同圆角白卡片。
- 不使用外链字体、图片素材或装饰性动画；视觉纹理通过轻量 CSS 实现。
- 收入和支出始终同时使用文字、符号和颜色表达，不单独依赖颜色。

### 2.3 信息架构

一级导航保留高频任务：

1. 月报 `/dashboard`
2. 流水 `/entries`
3. 预算 `/budgets`
4. 家庭 `/members`

低频管理入口放入“更多”菜单：分类、周期流水、操作日志和个人资料。CSV 导入导出放在流水页工具区，不创建孤立页面。

## 3. 功能设计

### 3.1 家庭预算

家长可以为指定月份设置一条家庭总预算，并可选地为支出分类设置分类预算。普通成员只读。预算按家庭和自然月隔离，不跨月自动继承。

月报展示：

- 总预算、已支出、剩余额度和使用率。
- 分类预算使用率，按接近超支和已经超支优先排序。
- 使用率小于 80% 为正常，80% 至 100% 为提醒，超过 100% 为超支。

预算删除为物理删除，因为预算是可重新创建的配置数据；删除操作写入操作日志。流水统计仍是预算使用额的唯一数据来源，不建立重复汇总表。

### 3.2 周期流水

家长和普通成员都可以创建属于自己的周期模板；家长还可以为本家庭其他活跃成员创建模板。模板包含成员、类型、分类、金额、每月发生日、备注和启用状态。

系统不增加后台调度器。用户在周期流水页面点击“生成本月流水”，系统生成当前月份已经到期且尚未生成的记录。每个模板每月最多生成一笔，数据库唯一约束保证重复点击和并发请求不会重复记账。

若发生日超过当月最后一天，则使用当月最后一天。停用分类或成员的模板不会生成，并返回可理解的跳过原因。用户可以停用、恢复、编辑或删除模板；删除模板不删除已经生成的历史流水。

### 3.3 CSV 导入导出

流水页支持导出当前筛选结果，字段固定为：发生日期、类型、分类、成员编号、金额、备注。导出遵循当前用户的权限范围，普通成员永远不能导出其他成员明细。

导入流程分两步：

1. 选择 UTF-8 CSV 后解析并预览，逐行显示标准化结果和错误。
2. 所有行有效时才能确认导入；确认后在一个事务内整批写入，任一行失败则整体回滚。

CSV 仅接受上述固定列名。类型接受 `INCOME/EXPENSE` 和中文 `收入/支出`；分类通过名称和类型匹配；成员通过成员编号匹配。普通成员导入时成员固定为本人。单次最多 500 行，避免课程演示环境被超大文件阻塞。

后端使用 Java 标准能力实现 CSV 转义与解析，不增加第三方依赖；前端使用浏览器 File API 和 Blob 下载。

### 3.4 统计增强与月报

月报接口在现有统计基础上增加：

- 当前范围与上一等长范围的收入、支出和结余环比。
- 储蓄率：收入大于零时为 `结余 / 收入`；无收入时返回空值而不是伪造 0%。
- 预算总额、预算使用额、使用率和分类预算状态。
- 分类异常增长：当前月某分类支出大于过去三个月该分类月均支出的 150%，且当前月支出不少于 100 元时提示；历史不足或基准为零时不提示。
- 可打印的月报视图，复用页面数据和浏览器打印样式，不在服务端生成 PDF。

现有 12 个月趋势、分类构成、成员比较和最近流水继续保留。统计始终基于流水实时聚合并过滤逻辑删除记录。

### 3.5 操作日志

操作日志记录具有家庭协作意义的写操作：成员资料和状态、分类、流水、预算、周期模板、CSV 导入及邀请码重置。

每条日志包含家庭、操作者、动作、对象类型、对象 ID、中文摘要和时间。摘要只保存答辩可读的信息，不保存密码、Session、Cookie、CSRF、数据库配置或完整请求体。

只有家长可以分页查看本家庭日志。日志不可从产品界面修改或删除。失败的业务操作不记录成功日志；日志与对应业务变更放在同一事务中，确保状态一致。

## 4. 数据模型与接口

### 4.1 新增数据表

通过 `V2__add_monthly_finance_features.sql` 新增：

- `monthly_budget`：`household_id`、`budget_month`、可空 `category_id`、`amount`、时间戳；家庭总预算和每个分类预算在一个月内唯一。
- `recurring_template`：家庭、成员、分类、类型、金额、发生日、备注、状态和时间戳。
- `recurring_generation`：模板、生成月份和生成的流水 ID；模板与月份唯一。
- `audit_log`：家庭、操作者、动作、对象类型、对象 ID、摘要和创建时间。

不修改已经执行的 V1。金额继续使用 `DECIMAL(12,2)`，月份使用每月第一天的 `DATE` 表示。

### 4.2 新增接口

- `GET /api/budgets?month=YYYY-MM`
- `PUT /api/budgets/total`
- `PUT /api/budgets/categories/{categoryId}`
- `DELETE /api/budgets/total?month=YYYY-MM`
- `DELETE /api/budgets/categories/{categoryId}?month=YYYY-MM`
- `GET/POST /api/recurring-templates`
- `PUT/DELETE /api/recurring-templates/{id}`
- `PATCH /api/recurring-templates/{id}/status`
- `POST /api/recurring-templates/generate?month=YYYY-MM`
- `GET /api/entries/export`
- `POST /api/entries/import/preview`
- `POST /api/entries/import/commit`
- `GET /api/audit-logs`

现有 `GET /api/statistics/dashboard` 扩充响应，不增加第二套统计接口。

## 5. 前端交互与修复

### 5.1 页面变化

- 月报页：采用批准的风格 C，增加环比、储蓄率、预算执行和异常提示。
- 预算页：月份选择、总预算编辑、分类预算列表和使用率。
- 流水页：增加导入、导出入口和周期流水入口；保留筛选和分页。
- 周期流水页：模板列表、创建编辑表单和“生成本月流水”操作。
- 家庭页：继续管理成员和邀请码。
- 操作日志页：家长可见的分页时间线。

### 5.2 已确认问题修复

- 使用本地日期而非 UTC 字符串生成流水默认日期。
- 监听 `/entries?new=1` 的 query 变化，并在抽屉关闭后清理 query。
- 每个页面只保留一个视觉主操作，避免全局和页面按钮竞争。
- 表单使用字段级错误并关联 `aria-describedby`。
- 图标按钮提供明确 `aria-label`；趋势图提供可读文本摘要。
- 辅助文字达到正常文本 4.5:1 的对比度目标，交互目标尽量达到 44px。
- 移动端采用紧凑顶部栏和底部主导航，不把四个完整文字标签挤在一行。

### 5.3 包体优化

- 页面使用路由级动态导入。
- Element Plus 改为按需组件和样式导入。
- ECharts 只注册折线图、饼图及使用到的组件和渲染器。
- 保持现有依赖版本，不引入新的 UI、图表或状态库。

目标是让主入口不再加载全部业务页面，并显著降低当前约 2.27 MB 的单体 JavaScript 产物；最终以实际构建产物为准，不预先承诺未经测量的具体百分比。

## 6. 权限、错误和一致性

- 所有数据查询首先限定当前家庭，普通成员的流水、导出、导入和周期模板再限定本人。
- 预算写入、他人周期模板和操作日志查看仅限家长。
- CSV 预览不写数据库；提交使用服务端重新校验，不能信任前端预览结果。
- 非法日期、月份、分页、枚举和 CSV 参数返回 400；无权限返回 403；不存在或不属于本家庭的对象按现有规则返回 404。
- 周期生成依靠数据库唯一约束实现幂等；预算更新依靠唯一约束和事务处理并发写入。
- 操作日志与业务操作同事务写入，日志写入失败时业务操作一起失败，不静默丢失审计记录。

## 7. 验收与测试

### 7.1 后端

- V2 在空库和已执行 V1 的数据库上都能成功迁移。
- 预算权限、唯一性、分类匹配、剩余额度和超支计算正确。
- 周期模板跨家庭隔离、普通成员权限、月底日期和重复生成幂等正确。
- CSV 引号、逗号、空行、中文类型、金额精度、500 行限制、预览和事务回滚正确。
- 环比、无收入储蓄率、异常阈值、逻辑删除过滤正确。
- 操作日志的权限、摘要脱敏和事务一致性正确。
- 原有注册、家庭、成员、分类和流水测试继续通过。

### 7.2 前端

- 新路由和权限守卫正确。
- 本地日期在 Asia/Shanghai 零点附近仍正确。
- 同路由“记一笔”可以重复打开并正确清理 query。
- 预算状态、CSV 预览错误、周期生成结果和日志分页可交互。
- 字段错误、图标标签和图表摘要可被测试定位。
- 390px 宽度无横向溢出，主导航和关键操作可用。

### 7.3 最终门禁

1. 后端 `mvnw.cmd clean verify`。
2. 前端类型检查、全部单元测试和生产构建。
3. 从当前源码启动临时专用数据库、后端和前端。
4. 家长与普通成员完成预算、周期生成、CSV、月报和日志的完整浏览器流程。
5. 在桌面和 390px 手机视口检查风格 C、可访问性和无横向溢出。
6. 检查实际 diff、构建产物、秘密信息、调试残留和报告一致性。

## 8. 实施分段与停止条件

实现按三个可独立验证的里程碑推进：

1. 视觉基础、日期/路由/可访问性修复和包体拆分。
2. 预算、周期流水和统计增强，形成完整家庭月报闭环。
3. CSV、操作日志、最终集成测试和报告材料更新。

以下内容明确不在本次范围：自动后台调度、消息提醒、Excel 专有格式、服务端 PDF、银行同步、多家庭切换、公网部署和生产级日志归档。

只有五项扩展、已确认前端修复、风格 C 桌面/移动布局及最终门禁全部通过时，才声明本次改造完成。
