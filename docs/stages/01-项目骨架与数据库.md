# 阶段一：项目骨架与数据库

## 1. 阶段目标

建立可重复启动的前后端工程和数据库基础，使后续业务开发有稳定边界。本阶段只做必要基础设施，不提前实现完整业务页面。

## 2. 输入与输出

**输入**：已确认的 [PRD](../01-PRD.md) 和 [架构设计](../02-架构设计.md)。

**输出**：

- 根目录 Git 忽略规则和运行说明骨架。
- `backend/` Java 17 + Spring Boot 工程、Maven Wrapper、基础健康检查和统一响应框架。
- `frontend/` Vue 3 + Vite + TypeScript 工程、路由骨架、Pinia、Axios 和基础样式 Token。
- 四张业务表、索引、系统默认分类和可重复执行的 Flyway 迁移。
- `demo` Profile 的幂等演示数据策略。

## 3. 范围边界

本阶段不实现登录业务、权限判定、业务 CRUD、统计图表或最终视觉细节；只为后续阶段提供可启动、可迁移、可测试的基础。

## 4. 计划文件与模块责任

| 位置 | 责任 |
|---|---|
| `backend/pom.xml`、`backend/mvnw*` | 固定 Java、Spring Boot、MyBatis-Plus、Flyway、MySQL 和测试依赖 |
| `backend/src/main/resources/application.yml` | 通用配置，只引用环境变量，不保存真实密码 |
| `backend/src/main/resources/application-demo.yml` | 本机演示 Profile 开关与非敏感默认值 |
| `backend/src/main/resources/db/migration/` | Schema、索引和系统分类迁移 |
| `backend/.../common/` | 成功/错误响应、异常处理和分页基础 |
| `frontend/package.json`、lockfile | 固定 Vue、Vite、Element Plus、ECharts 等依赖和命令 |
| `frontend/src/router/` | 八个路由占位与基础 404 |
| `frontend/src/styles/` | 颜色、圆角、间距、动效 Token 和全局重置 |
| 根目录 `README.md` | 环境、配置和启动说明，后续阶段持续补充 |

## 5. 实施任务

1. 检查工作区已有文件并保护用户资料，初始化本地 Git；不连接远程仓库、不推送。
2. 创建 Spring Boot 工程，配置 Java 17、UTF-8、测试框架和 Maven Wrapper。
3. 配置数据库连接环境变量示例，例如数据库地址、库名、用户名和密码；真实值放在本机环境，不提交源码。
4. 编写第一版 Flyway 迁移，创建 `household`、`app_user`、`finance_category`、`ledger_entry` 及架构文档规定的唯一索引和查询索引。
5. 插入不可修改的系统收入/支出默认分类；迁移脚本一经进入使用，不回写旧迁移，后续变更新建版本。
6. 创建 Vue 工程并安装已批准依赖，定义 `dev`、`build`、`type-check`、`test:unit` 命令以及 `/api` 开发代理。
7. 建立八个路由的最小占位页面、全局 Token 和 Axios 基础实例，不编写虚假静态业务数据。
8. 设计 `demo` Profile 初始化器：仅在演示环境检查是否已有标记账号，没有时才创建；具体账号和流水在后续业务模型完成后补齐。
9. 补充 README 的工具版本、MySQL 建库要求、环境变量示例和两端启动命令。

## 6. 数据库检查点

- 表名、字段类型和外键与架构文档一致。
- 金额为 `DECIMAL(12,2)`；日期使用 `DATE`；逻辑删除字段有默认值。
- 用户名、邀请码、家庭成员编号、家庭自定义分类名称的唯一性可由数据库约束兜底。
- 流水至少有覆盖 `(household_id, occurred_on)` 的索引；成员、类型和分类筛选不进行无必要的全库扫描。
- 演示初始化不会在普通 Profile 运行，也不会重复制造数据。

## 7. 验证与验收

| 验收项 | 验证方式 | 通过标准 |
|---|---|---|
| 后端基础构建 | `mvnw.cmd test` | 编译和基础上下文测试通过 |
| 数据库迁移 | 对空测试库启动两次 | 首次建表，第二次无重复执行错误 |
| 前端类型和构建 | `npm run type-check`、`npm run build` | 无类型或构建错误 |
| 开发代理 | 两端启动后请求 `/api` 健康接口 | 浏览器通过 Vite 代理得到 JSON |
| 配置安全 | 搜索项目配置和 diff | 无真实密码、Cookie、令牌或个人信息 |

## 8. 常见失败与处理

- **MySQL 版本或字符集不符**：统一使用 MySQL 8.x 和 `utf8mb4`，修正本地数据库后重跑空测试库。
- **迁移已经部分执行**：只处理专用开发/测试库；先确认目标库再重建，不对用户其他数据库做删除操作。
- **依赖版本冲突**：以架构文档的主技术栈为准，删除非必要插件，不引入第二套 UI、ORM 或认证库。

## 9. 停止条件与阶段证据

两端从各自源码可启动、空库迁移成功、路由占位可访问且基础构建通过即停止。本阶段不因为“顺便方便”继续做业务功能。记录工具版本、迁移结果和构建退出码后进入阶段二。
