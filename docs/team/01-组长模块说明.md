# 组长模块说明

## 1. 责任目标

以下是“组长”角色的建议责任边界，用于交接和答辩准备，不核实任何个人已经完成的工作。建议范围包括把任务书转化为可实施的产品边界和技术架构，建立数据库与安全基座，完成认证、家庭和个人资料闭环，并统筹模块集成、运行说明和最终验收；该角色既包含代码，也包含跨模块决策与质量控制。

## 3. 实现逻辑

### 3.1 注册与登录

1. `AuthController` 接收注册或登录请求，Bean Validation 先检查字段格式。
2. 注册时 `AuthService.register()` 将用户名和姓名去除首尾空格，检查用户名全局唯一，使用 BCrypt 保存密码摘要，新账号初始未加入家庭。
3. 登录时 `AuthenticationManager` 调用 `UserDetailsServiceImpl` 查询账号并校验密码；成功后把认证对象写入服务端 Session，安全配置声明 `changeSessionId()`。当前验收记录未把登录后 Session ID 的实际轮换作为独立已验证证据。
4. 浏览器先获取 CSRF Token，所有修改请求由 Axios 携带 `X-XSRF-TOKEN`；未登录返回 401，无权限返回 403。

### 3.2 当前用户与家庭隔离

`CurrentUserService.requireUser()` 每次从 Spring Security 上下文取得用户名，再查询数据库确认账号仍为 ACTIVE。业务代码不接受客户端传入的 `householdId` 作为可信条件，而是使用当前用户的 `householdId`。这样即使用户修改请求参数，也无法访问另一家庭的数据。

### 3.3 创建家庭

`HouseholdService.create()` 在事务内完成：检查用户尚未入户；生成唯一 8 位邀请码；插入家庭；把创建者更新为 `M001/PARENT`。家庭和用户更新要么一起成功，要么一起回滚。

### 3.4 邀请码加入

`join()` 将邀请码标准化为大写，先定位家庭，再对家庭记录加锁复核邀请码；随后读取并锁定当前最大成员序号，生成下一个 `Mxxx`，把用户设置为该家庭的普通成员。锁与家庭内唯一索引共同避免并发加入产生重复编号。

### 3.5 重置邀请码

`rotateInviteCode()` 先通过 `requireParent()` 确认家长身份，再锁定当前家庭并生成新码。数据库的唯一索引是最终一致性保护，旧邀请码在事务提交后立即失效。

### 3.6 修改资料与密码

资料修改只允许更新本人姓名。密码修改先校验旧密码，再保存新的 BCrypt 摘要；前端成功后主动退出并回到登录页，要求用新密码重新登录，避免旧会话继续长期有效。

## 4. 跨模块接口与审核重点

- 向组员一提供 `CurrentUserService`、统一异常、八表关系和家庭范围查询原则。
- 向组员二提供认证恢复、CSRF、401/403、统一 `{ data }`/错误结构和接口清单。
- 审核所有后端业务是否先限制当前家庭，再做对象 ID 查询和角色判断。
- 负责最终运行 Maven、前端类型检查/测试/构建以及真实浏览器流程。

## 5. 组长验收清单

- 注册、登录、退出、刷新恢复和停用账号失效均正确。
- 新用户只能创建或加入一个家庭；邀请码唯一且可重置。
- 家庭 ID 不由前端决定；跨家庭成员、分类、流水和统计均隔离。
- 数据库迁移可在空库执行，demo 初始化可重复启动。
- 三个模块接口与前端类型一致，README 能在本机重现演示。
