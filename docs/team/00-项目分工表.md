# 家庭理财系统三人分工表

## 1. 使用说明

本表用于课程设计的小组责任划分、开发交接和答辩准备。分工描述的是应承担和应讲解的责任范围；最终个人报告中的“本人完成”应以实际接手、修改、测试和答辩准备记录为准，不以本表代替事实证据。

成员信息暂用占位符，提交前统一替换：`[组长姓名]`、`[组员一姓名]`、`[组员二姓名]`。

## 2. 总体分工

| 成员 | 角色 | 主责范围 | 核心交付物 | 验收责任 |
|---|---|---|---|---|
| [组长姓名] | 组长 | 需求与架构、数据库、安全认证、家庭创建/加入、个人资料、项目集成与最终验收 | PRD、架构设计、数据库迁移、认证与家庭模块、运行说明、最终验收记录 | 保证系统可启动、权限边界正确、各模块可联调、文档与源码一致 |
| [组员一姓名] | 组员一 | 后端业务：成员、分类、收支、统计及其后端测试 | 四个业务模块的 Controller/Service/Mapper/DTO，业务规则与后端测试说明 | 保证 CRUD、统计精度、家庭隔离和角色权限符合任务书 |
| [组员二姓名] | 组员二 | 前端应用：页面壳、路由状态、业务页面、统计图表、响应式与前端测试 | Vue 页面、API 封装、Pinia、路由守卫、图表、移动端与前端测试 | 保证主要用户动线、错误状态、桌面/手机交互可演示 |

## 3. 模块所有权与协作边界

| 模块 | 主责 | 配合方 | 交接接口 |
|---|---|---|---|
| 需求、架构、数据库、安全 | 组长 | 两位组员评审 | `docs/`、数据库约束、统一响应、会话身份 |
| 认证、家庭、资料 | 组长 | 组员二接页面 | `/api/auth/*`、`/api/households/*`、`/api/profile/*` |
| 成员、分类、收支、统计后端 | 组员一 | 组长审核权限，组员二接接口 | `/api/members`、`/api/categories`、`/api/entries`、`/api/statistics/dashboard` |
| 前端应用与视觉 | 组员二 | 组长确认动线，组员一确认字段 | `frontend/src/api/`、`types/` 与后端 DTO 对齐 |
| 最终联调与交付 | 组长 | 两位组员执行各自检查 | Maven/Vitest/TypeScript/Vite 门禁和浏览器演示 |

## 4. 每人必须能回答的答辩问题

- 全员：系统解决什么问题、家长与普通成员权限差异、四张表的关系、一次完整用户动线。
- 组长：为什么使用前后端分离、Session 与 CSRF 如何配合、家庭 ID 为什么不信任前端、邀请码并发与最后家长约束如何保证。
- 组员一：成员/分类/流水的业务校验顺序、逻辑删除、分页筛选、统计口径、如何防止跨家庭访问。
- 组员二：路由守卫和 401/403 分流、表单联动、ECharts 数据映射、桌面表格与手机卡片切换、状态管理和测试方式。

## 5. 提交前核对

1. 将所有姓名、学号、班级和指导教师占位符替换为真实信息。
2. 三份报告的详细设计只保留该成员实际负责的代码，不互相复制个人实现章节。
3. 个人总结依据各自真实问题、修改和测试记录补充，不编造提交或工作过程。
4. 统一使用最终系统截图，图片不得出现密码、Cookie、Token 或私人路径。
