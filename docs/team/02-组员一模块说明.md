# 组员一后端业务模块说明

## 1. 责任目标

以下是“组员一”角色的建议责任边界，用于交接和答辩准备，不核实个人实际贡献。建议范围是把成员、分类、收支、预算、周期流水、CSV、统计和审计等后端业务做成可验证闭环；重点不是简单 CRUD，而是确保角色权限、家庭隔离、业务校验、逻辑删除和金额统计一致。

## 3. 实现逻辑（建议讲解口径）

### 3.1 成员管理

查询成员时用当前会话的家庭 ID；普通成员可以查看名单，但修改接口首先调用 `requireParent()`。更新时 `targetInHousehold()` 同时校验成员 ID 与当前家庭，防止跨家庭对象引用。若修改成员编号，检查家庭内唯一；若把家长降为普通成员或停用家长，先统计其他活跃家长，最后一名家长不能被降级或停用。

### 3.2 分类管理

列表同时返回系统预置分类和当前家庭自定义分类。系统分类 `household_id` 为空、只读；家庭分类由家长创建和维护。新建/修改时检查类型与同家庭同类型名称冲突；停用分类后不能用于新流水，但历史流水保留分类名称并继续统计。

### 3.3 收支列表

`EntryQuery.normalized()` 统一页码和每页数量。`LedgerService.list()` 首先确定当前家庭；普通成员把成员条件强制为本人，家长才允许按任意本家庭成员筛选。查询条件包括日期、类型、类别、成员和 `deleted=false`，按发生日期、创建时间倒序返回。

### 3.4 新增与修改流水

处理顺序为：读取当前用户 → 确定目标成员 → 验证成员属于当前家庭且可用 → 验证分类为系统分类或当前家庭启用分类 → 验证分类类型与流水类型一致 → 验证金额大于零、日期不晚于今天 → 清理备注 → 保存。普通成员的目标成员被强制为本人，家长可为全家成员记账。

修改和删除先通过 `target()` 查询当前家庭内未删除流水，再校验普通成员只能操作本人记录。删除只把 `deleted` 设置为 true，列表和统计统一过滤逻辑删除记录。

### 3.5 统计口径

统计接口只接受起止日期，不接受家庭 ID。服务以当前家庭过滤所有数据：收入总额、支出总额和结余使用 `BigDecimal`；趋势返回截止月份往前 12 个月并对无数据月份补零；类别构成按收入/支出和分类汇总；成员对比同时给出收入、支出和结余；最近流水复用统一响应格式。

### 3.6 月报增强口径

- 预算按自然月保存总预算或支出分类预算，普通成员只读执行结果，家长可保存或删除配置；执行额直接从未删除支出流水聚合。
- 周期模板由用户主动指定月份生成，不依赖后台调度器；每个模板每月最多生成一笔，发生日超过月底时使用月底日期，成员或分类不可用时返回跳过原因。
- CSV 预览不写库，提交时后端重新解析并校验 checksum，任一行失败则整批不写入；导出复用当前用户的家庭/本人范围。
- 关键业务写操作写入 `audit_log`，日志查询只开放给家长；摘要不写入密码、Cookie 等敏感信息。

## 4. 关键业务不变量

- 任意成员、分类、流水 ID 在使用前必须验证属于当前家庭。
- 普通成员只能增删改查本人流水，家长可维护全家流水。
- 系统分类不可修改；停用分类不能用于新数据，历史数据不丢失。
- 最后一名活跃家长不能停用或降级。
- 金额用 `DECIMAL(12,2)`/`BigDecimal`，不能用浮点数。
- 逻辑删除后的流水不出现在列表、统计和最近记录中。
- 当前最终 Schema 为 V1 四张基础表 + V2 四张增强表，共八张业务表；`monthly_budget`、`recurring_template`、`recurring_generation`、`audit_log` 分别承载预算、周期生成和审计闭环。

## 5. 测试与验收

至少覆盖：跨家庭对象拒绝、普通成员访问他人流水拒绝、家长操作全家流水、最后家长保护、分类类型不匹配、未来日期拒绝、金额精度、逻辑删除、统计收入/支出/结余、预算家长写/成员只读、周期模板本人范围与重复生成、CSV 预览/事务导入和审计日志权限。测试数据库必须是专用库，不能使用个人已有业务数据库。实际已通过的命令、用例数量和接口 smoke 范围见阶段五，不把定向证据写成完整 CRUD 或全项目无缺陷。

## 6. 建议答辩演示

使用家长账号新增一笔普通成员支出，再切换普通成员账号验证只能看到本人明细；停用一个自定义分类并说明历史流水仍保留；删除一条流水后观察列表和统计同步变化；最后说明服务层“当前家庭 + 当前角色 + 目标对象”的三重校验。
