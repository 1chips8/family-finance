# 阶段五：测试、验收与报告素材

## 1. 阶段目标

在不扩展功能的前提下收敛缺陷，证明系统由当前源码可构建、可启动、权限正确、演示完整，并生成课程报告需要的真实素材。

## 2. 依赖与输出

**进入条件**：阶段四统计正确、全部页面可用且无已知阻断问题。

**输出**：

- 后端和前端最终门禁结果。
- 从当前源码启动后的完整演示验收记录。
- README 最终运行说明和演示账号。
- 架构图、ER 图、页面截图、测试摘要和报告章节素材清单。
- 明确的遗留问题记录；不在本阶段临时添加新功能。

## 3. 收敛顺序

1. 冻结需求，以 PRD 验收项建立检查表。
2. 运行后端相关测试，修复权限、数据一致性和业务规则问题。
3. 运行前端类型检查与单元测试，修复路由、表单和错误状态问题。
4. 执行最终生产构建，检查实际变更、配置秘密和生成物。
5. 从当前源码启动两端，按演示脚本完成浏览器验收。
6. 在验收通过的界面上统一截图并整理报告素材。

## 4. 最终自动化门禁

```powershell
cd backend
.\mvnw.cmd clean verify

cd ..\frontend
npm run type-check
npm run test:unit
npm run build
```

通过标准：所有命令退出码为 0；测试不是因跳过、过滤错误或未发现测试而“伪通过”。若 Testcontainers 受本机环境阻塞，必须说明原因并使用专用 MySQL 测试库重新执行同等集成用例。

## 5. 完整演示脚本

1. 启动 MySQL、后端和前端，打开系统并确认无需公网资源。
2. 注册账号 A，创建家庭并记录邀请码；确认 A 为家长。
3. 注册账号 B，用邀请码加入；确认 B 为普通成员。
4. A 新建收入和支出分类，分别为 A、B 记录多笔跨月流水。
5. B 登录，确认只看到和维护本人明细，但能看到家庭聚合统计。
6. B 尝试成员管理、分类管理和他人流水接口，确认被拒绝。
7. A 修改成员编号/姓名，停用并恢复一个分类；确认历史数据保留。
8. A 删除一条流水，确认列表和统计同步排除。
9. A 尝试停用或降级最后一名家长，确认操作失败且数据不变。
10. 刷新、退出、重新登录，并在手机宽度完成一次新增收支。

演示中每一步记录“账号、操作、预期、实际结果”，失败时先修复根因，再从受影响步骤重验。

## 8. README 最终检查

- Java、Node、MySQL 的版本要求。
- 数据库创建、环境变量示例和 Flyway 自动初始化说明。
- 后端与前端的精确启动/测试/构建命令。
- `demo` Profile 演示账号、密码和数据范围。
- 推荐演示顺序以及端口占用、数据库连接、CSRF 等常见问题。
- 明确这是本机课程设计，不包含公网部署说明。

## 9. 缺陷优先级与退出规则

- **必须修复**：无法构建/启动、数据串户、越权、统计错误、数据丢失、主流程中断、报告与源码明显不一致。
- **本阶段酌情修复**：影响演示的布局、文案、响应式和一般交互问题。
- **记录但不扩展**：预算、导出、通知、附件、更多图表、动画和生产部署设想。

## 10. 停止条件与最终证据

只有以下条件同时满足才可声明课设系统完成：

1. 最终自动化门禁对当前源码全部通过。
2. 完整演示脚本通过，关键失败路径与权限边界得到验证。
3. 实际 diff 无秘密、调试残留、无关生成物或越界功能。
4. README 能让同一台本机按说明重新启动。
5. 报告素材来自最终系统，且计划、源码、截图和文字一致。

若任一项未满足，应明确写为“未完成/受阻”，记录已完成验证和剩余风险，不用页面可打开或部分测试成功代替最终结论。
